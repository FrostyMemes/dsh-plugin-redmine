# Redmine для DeepSeek Harness

Отдельный устанавливаемый плагин: глобальный список задач Redmine, фильтры, ручное обновление, выбор workspace и запуск задачи в новую или существующую сессию DSH. Интерфейс — на русском языке. Исходные требования: [ТЗ](books/DSH_Redmine_Plugin_TZ_MVP.md) и [дополнения](books/MVP_ADDITIONS.md).

## Состояние

Целевая сборка — **DSH Desktop 0.2.1-rc.3**, корпоративный **Redmine 4.1.x** (ветка установлена пользователем; точный patch неизвестен). Поддержка опирается на базовые REST endpoints с проверкой доступности через настройки. Сам плагин ещё не проверен на корпоративном сервере.

`mockEnabled` включён по умолчанию. Панель показывает синтетические данные и не вызывает сетевой транспорт Redmine. Выключение флага включает настоящий REST API, без автоматической подмены ошибок моками. Изменение задач Redmine плагином не предусмотрено.

## Подготовка и локальный запуск

Нужны Node.js 22+ и установленная DSH указанной версии. В PowerShell из корня репозитория:

```powershell
npm ci --legacy-peer-deps --ignore-scripts
.\scripts\dev-host.ps1
```

Если DSH находится в другом месте:

```powershell
.\scripts\dev-host.ps1 -DshCommand 'C:\path\to\DSH\resources\runtime\cli\bin\dsh.cmd' -Port 64620
```

Скрипт собирает Bundle, создаёт отдельный профиль `redmine-dev` и запускает Web UI. Откройте **ссылку, напечатанную DSH в терминале**, включая временный token для входа. Не публикуйте её. Тестовый профиль, данные и pnpm store находятся в игнорируемой папке `.dev`. Настройки, ключи и агентные MCP обычного профиля не копируются.

Для повторной сборки остановите тестовый Host и повторно запустите скрипт. Обычный установленный Desktop и его профиль скрипт не изменяет. Локальный тестовый профиль сохраняет режимы между запусками: перед проверкой без Redmine убедитесь, что моки включены.

## Установка Bundle в свой профиль

Сначала создайте архив:

```powershell
npm run build
npm pack --pack-destination .dev
```

В DSH откройте **Plugins → Add plugin** и укажите абсолютный путь к полученному `.tgz`. Альтернатива через CLI:

```powershell
dsh plugin --profile <ваш-профиль> add 'C:\path\to\dsh-plugin-redmine-0.2.2.tgz'
```

Перезапустите профиль при запросе DSH. В глобальной навигации появится **Redmine**, а на странице Bundle — настройки плагина.

## Начало работы

1. Откройте Redmine. Первоначально включены моки, фильтры «Мои задачи» и открытые статусы.
2. Откройте настройки через шестерёнку или страницу плагина в DSH. Переключатели демонстрационных данных, режима разработчика и запуска сессий в режиме планирования сохраняются сразу. Флажок «Запускать сессию в режиме планирования» находится в блоке «Запуск сессии» и по умолчанию выключен. Нажмите на пример переменной рядом с заголовком шаблонов, чтобы вставить тег в позицию курсора или выделенный фрагмент текста промпта.
3. На главной вкладке Redmine кнопка **«Открыть логи»** доступна при включённом режиме разработчика. Выбор сценария появляется там же только при одновременно включённых моках и режиме разработчика; выбор сразу сохраняется и обновляет список.
4. У задачи отдельно выберите существующий workspace или каталог Host. Плагин не создаёт папки; зарегистрированный каталог переиспользуется.
5. Нажмите **«В работу»**: создаётся настоящая сессия DSH с названием задачи. Название проходит штатную нормализацию и ограничение длины DSH. Если у задачи есть доступные сессии, диалог позволяет выбрать одну из них: выбранный шаблон отправится в эту сессию, и она откроется. Можно отменить действие или создать новую сессию. Выбранная существующая сессия открывается независимо от настройки «Открывать созданную сессию»; эта настройка относится к новым сессиям. Для новой сессии настройка планирования включает нативный режим; если DSH не предоставляет его для выбранного preset, запуск завершится понятной ошибкой без отправки промпта. Для моков сессия получает тестовый промпт с просьбой подтвердить запуск без обращения к Redmine/MCP и изменения файлов.

Когда появится доступ к Redmine, сохраните HTTPS URL и персональный ключ, выключите моки и нажмите **«Проверить подключение»** в блоке подключения. Кнопка проверяет сохранённые реквизиты; если URL или ключ изменены, сначала нажмите **«Сохранить подключение»**. Результаты отображаются в этом же блоке: пользователь, проекты, задачи, справочники, HTTP-коды и причины отказов. Кнопка **«Очистить поле проверок»** удаляет сохранённый результат; следующая проверка покажет новые строки. В mock-режиме проверка явно сообщает, что реальный сервер не проверялся. Некоторые ответы сервера не позволяют однозначно различить неверный ключ и отключённый REST API.

| Демонстрационные данные | Режим разработчика | Сценарии на вкладке Redmine | Открыть логи |
|---|---|---|---|
| Включены | Включён | Доступны, сохраняются сразу | Доступно |
| Включены | Выключен | Скрыты | Скрыто |
| Выключены | Включён | Скрыты | Доступно для настоящего API |
| Выключены | Выключен | Скрыты | Скрыто |

## Редактор шаблонов

В настройках используется один редактор. Выберите сохранённый шаблон из списка для изменения либо нажмите «Создать шаблон». Эта кнопка готовит черновик с названием «Новый шаблон», текстом «Новый промпт» и выключенной отметкой по умолчанию. Черновик появляется в списке сохранённых шаблонов только после успешного сохранения.

Значок ⓘ у заголовка шаблонов открывает подсказку о каждой поддерживаемой вставке при наведении или фокусе с клавиатуры; Escape закрывает подсказку. Нажатие на тег в подсказке вставляет его в позицию курсора или выделенный фрагмент в поле «Текст промпта шаблона».

Сохранение выполняется по названию с удалением пробелов по краям. При существующем названии открывается диалог «Такой шаблон уже существует. Перезаписать его?»: «Перезаписать» обновляет соответствующий шаблон, «Отмена» сохраняет черновик без изменения коллекции. Подтверждение требуется и при редактировании выбранного существующего шаблона. Новое название добавляет шаблон с отдельным ID и сохраняет прежний. Имена различаются по регистру. При совпадении названий, оставшихся от старой версии, приоритет имеет выбранный шаблон с таким названием. В сохранённой коллекции всегда один шаблон по умолчанию; удалить последний шаблон нельзя.

Сообщения «Настройки подключения сохранены», «Режим сохранён» и «Шаблон сохранён» отображаются рядом со своим блоком. В списке статусов используется единый выбор «Все статусы» или отдельных серверных статусов.

## Диагностика

Журнал содержит `debug`, `info`, `warning`, `error`: параметры разрешённых операций, ошибки запросов и запуска, перехваченные ошибки Host, React и браузера. Нативный Cordis logger подключён только для записей Redmine; журнал всех остальных плагинов и личные сессии DSH не копируются.

Хранение — отдельный durable domain DSH `redmine_plugin`, ограниченный последними 7 днями и 20 МБ. Журнал продолжает собираться при закрытом окне. Просмотр и выгрузка требуют включённого режима разработчика и прав владельца DSH. Последние записи обновляются, пока окно открыто. Данные проходят очистку; ключи, cookies, полные ответы задач и промпты не журналируются.

Ошибки TypeScript появляются **при компиляции**, поэтому для них предусмотрен отдельный канал разработки:

```powershell
npm run typecheck
```

Команда печатает результат и обновляет `.dev/build-diagnostics.json`. Профиль, запущенный `dev-host.ps1`, импортирует новый результат в журнал при его открытии/обновлении в режиме разработчика. Production Bundle не запускает компилятор. Путь к артефакту подключается только конфигурацией Host `developmentDiagnosticsFile`, без доступа браузера к файловой системе.

Ошибка, из-за которой сам Bundle не может загрузиться, доступна в диагностике DSH/терминале: неработающий плагин не может открыть собственное окно.

## Границы доступа

Ключ хранится в DSH credentials под ссылкой `DSH_REDMINE_API_KEY` и не возвращается интерфейсу. Новый плагин обращается к Redmine только GET-запросами. Описания, комментарии и вложения панель не запрашивает специально и не сохраняет из ответа списка. Для устойчивого повтора Host сохраняет сформированный текст промпта; при успешной отправке и при окончательном отказе до отправки снимок удаляется. При промежуточном сбое он остаётся для повтора с тем же текстом. Промпт не попадает в Launch DTO и журнал. Если в старой незавершённой операции такого снимка нет, её повтор с прежним ID блокируется: начните новую операцию через «В работу».

Обычная агентная сессия использует существующие MCP/skills и их реальные права. Инструкция «не изменять Redmine» и тестовый mock-промпт не являются технической блокировкой сторонних MCP. Для строгого запрета записи нужны соответствующие ограничения существующей интеграции.

## Проверки и разработка

```powershell
npm run build
npm test
```

В репозитории есть регрессионные проверки транспорта, mock-режима, health check, фильтров, запуска, изоляции подключений и диагностики. Браузерную проверку этой итерации по решению пользователя выполняет пользователь. Фактически выполненные проверки и ограничения фиксируются в [отчёте совместимости](books/COMPATIBILITY.md).

Ветки: `feature/*` / `fix/*` от `dev`, затем интеграция в `dev`. Слияние в `master` сейчас запрещено. Для кодирования используется GPT-6 Luna с reasoning `xhigh`; проектная роль описана в `.codex/agents/coder.toml` по [формату custom agents](https://learn.chatgpt.com/docs/agent-configuration/subagents#custom-agents).
