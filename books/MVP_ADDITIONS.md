# Дополнения к MVP от 25.10.2026

Согласованы пользователем после исходного ТЗ.


- Целевая DSH Desktop — `0.2.1-rc.3`. Уточнение пользователя от 26.10.2026: корпоративный Redmine **4.1.x**, точный patch неизвестен. Наличие API более новых веток не предполагается.
- Два источника данных с одинаковым контрактом панели: Host REST GET и локальные моки. `mockEnabled=true` по умолчанию. При включении нет сетевых запросов плагина к Redmine; выключение не допускает автоматического fallback.
- Моки покрывают несколько страниц, разные словари, пустые проекты, одинаковые названия категорий с разными ID, ошибки и задержки.
- В mock-режиме workspace и сессии настоящие. Тестовый промпт обозначает синтетические данные, запрещает обращения к Redmine/MCP и изменения файлов. Это инструкция агенту, не техническая блокировка его инструментов.
- Из настроек обязательна проверка пользователя, проектов, задач и справочников с временем, этапами, HTTP-кодами и понятной причиной. Частичная доступность отображается отдельно от полного успеха. Mock health check явно не проверяет сервер.
- `developerMode=false` по умолчанию. Структурированные `debug/info/warning/error` сохраняются на Host: 7 дней, до 20 МБ. Окно с фильтрами и выгрузкой доступно только в режиме разработчика; проверка доступа выполняется на Host.
- В журнал не включаются секреты, полные ответы задач и промпты. Ошибка журнала не останавливает продукт.
- Поиск и неподтверждённые комбинации фильтров могут обрабатываться на Host после контролируемой выборки до 10 000 задач; ограниченная полнота явно обозначается.
- Git: `master` → `dev` → `feature/*`/`fix/*` → `dev`; слияние текущего MVP в `master` запрещено. Реализация остаётся в `feature/redmine-mvp`.
- Дополнение пользователя: журнал включает реальные исключения Host, ошибки рендера React и браузерного runtime, а при разработке — диагностику компилятора TypeScript. Компиляторные ошибки импортируются из отдельного локального артефакта разработки; production Bundle не запускает компилятор.
- Для кодирования использовать GPT-6 Luna с reasoning `xhigh`. Проверку интерфейса текущей итерации пользователь выполняет самостоятельно; это не считается подтверждённой браузерной проверкой со стороны агента.

## Уточнения интерфейса от 26.10.2026

- Режим разработчика независим от mock-режима: журнал работает и с демонстрационными данными, и с реальным API.
- Переключатели режимов в настройках сохраняются сразу; кнопка «Сохранить режимы» удалена.
- Выбор сценария перенесён на главную вкладку Redmine. Он виден только при одновременно включённых `developerMode` и `mockEnabled`, сохраняется при выборе и сразу запускает обновление списка.
- Кнопка «Открыть логи» размещена только на главной вкладке Redmine и видна при `developerMode=true` независимо от источника данных.
- Отдельные блоки «Проверка здоровья» удалены. Проверка и её результаты находятся в блоке подключения настроек; кнопка называется «Проверить подключение» и проверяет сохранённые реквизиты. Сохранение URL/ключа остаётся отдельной операцией.

## Уточнения интерфейса 0.1.2

- Настройки занимают доступную ширину контейнера. Главная вкладка Redmine и её настройки имеют собственную вертикальную прокрутку; компактная строка возврата не занимает высоту всей страницы.
- Один редактор шаблона вместо растущего списка карточек. Сохранённые шаблоны выбираются из dropdown; «Сохранить шаблон» обновляет шаблон с существующим названием либо добавляет новый при новом названии. Существующий ID сохраняется при перезаписи. Ввод названия обрезается по краям, регистр учитывается; выбранный шаблон приоритетен среди старых дубликатов имени.
- Поле промпта называется «Текст промпта шаблона». Отметка по умолчанию сохраняется вместе с шаблоном; коллекция сохраняет ровно один default и хотя бы один шаблон.
- Отдельные зелёные уведомления у блоков: «Настройки подключения сохранены», «Режим сохранён», «Шаблон сохранён».
- «Открыть логи» визуально представлено подчёркнутым текстом с семантикой доступной кнопки.
- Фильтр статусов соответствует остальным мультиселекторам: «Все статусы» или набор конкретных статусов. Отдельные группы и разделитель «Или выбрать статусы» удалены. Старые сохранённые группы open/closed отображаются через серверные признаки статусов; начальный фильтр открытых задач сохраняется.
- Новая сессия получает название задачи через штатный `sessionController.rename` до отправки промпта. Ограничение длины и нормализация делегированы DSH; принятый пользовательский title защищён штатным механизмом DSH от автоматического переименования. Успешное назначение имени сохраняется как этап запуска для безопасного повтора.
- Проверка существования использует поле `sessionId` официального `SessionSummary`; ошибочное чтение `id` исправлено. Переход делегируется `uiWorkspace.openSession`, который сам раскрывает беседу.

## Создание шаблонов 0.1.3

- Один редактор сохраняется. Кнопка «Создать шаблон» подготавливает только черновик: «Новый шаблон», «Новый промпт», default=false. Запись в сохранённой коллекции и новый пункт dropdown появляются только после успешного сохранения.
- Совпадение имени при любом сохранении требует диалога «Такой шаблон уже существует. Перезаписать его?» с действиями «Перезаписать» и «Отмена». До подтверждения запрос записи не выполняется; отмена сохраняет черновик и прежнюю коллекцию.
- Подтверждённая перезапись сохраняет существующий ID и заменяет текст и отметку default выбранными в редакторе. Сравнение имён остаётся регистрозависимым после trim.
- В сохранённой коллекции всегда ровно один default. Новый черновик не меняет сохранённый default. У единственного сохранённого шаблона default снять нельзя; при подтверждённой перезаписи единственной записи она остаётся default.

## Подсказка переменных шаблона 0.1.4

- Постоянная строка «Доступные поля» заменена значком ⓘ. При наведении и фокусе раскрывается пояснение всех девяти поддерживаемых вставок: ID/URL/название задачи, ID/название проекта Redmine, статус, трекер, приоритет и путь workspace Host. Escape закрывает подсказку.

## Endpoints инстанса — 26.10.2026

Предоставленный пользователем список зафиксирован в [REDMINE_ENDPOINTS.md](REDMINE_ENDPOINTS.md). Категории и типы задач получать через детали проекта с `include=trackers,issue_categories`; неподтверждённый общий endpoint типов задач не вызывать. Список не расширяет read-only границы панели: пишущие endpoints и полное содержимое задач остаются вне MVP. Доступ к корпоративному серверу и его точная версия по-прежнему не проверены.
