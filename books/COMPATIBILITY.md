## Redmine

Пользователь 26.10.2026 эмпирически установил ветку корпоративного сервера: **Redmine 4.1.x**. Точный patch, права и изменения инстанса неизвестны; подключение плагина к серверу ещё не проверялось. Годы 2022–2023 и copyright в подвале сами по себе не определяют номер версии.

В исходниках официального зеркала ветки `4.1-stable` проверены [выдача деталей проекта](https://github.com/redmine/redmine/blob/4.1-stable/app/views/projects/show.api.rsb), [вложенные trackers/issue_categories](https://github.com/redmine/redmine/blob/4.1-stable/app/helpers/projects_helper.rb) и [постраничный API списка задач](https://github.com/redmine/redmine/blob/4.1-stable/app/controllers/issues_controller.rb). Формат вложенных справочников соответствует реализации 0.1.5. Это сверка с исходниками ветки, не проверка фактической корпоративной сборки.

Реализация использует базовые GET endpoints: `users/current.json`, `projects.json`, `issues.json`, `issue_statuses.json`, `enumerations/issue_priorities.json` и детали проекта с `include=trackers,issue_categories`. Общий `trackers.json` не вызывается: типы задач собираются из деталей доступных проектов. Отдельный endpoint категорий заменён согласно списку маршрутов инстанса, предоставленному пользователем; [карта endpoints и границы использования](REDMINE_ENDPOINTS.md). Не предполагаются современные endpoint health/version либо расширенные фильтры. Пользователь текущего API нормализуется из `firstname/lastname/login`; названия словарей читаются с сервера.

Форматы тестовых ответов и границы базового поведения сверены с [Users API](https://www.redmine.org/projects/redmine/wiki/Rest_Users) и [Issues API](https://www.redmine.org/projects/redmine/wiki/Rest_Issues). Эти документы не заменяют проверку корпоративной установки.

Поиск по заголовку, сочетания фильтров и сортировка выполняются на Host по метаданным: новые операторы серверного поиска не требуются. Запросы ограничены GET с заголовком API-ключа, страницы — максимум 100 записей. Возможности `allowed_statuses`, `enabled_standard_fields`, новые endpoints версий/health и версия API в URL не используются. Это проверка контракта исходников ветки; точный patch и права корпоративного сервера требуют отдельного подключения.

Добавлены две целевые проверки `test/redmine-41.mjs`: синтетические ответы формата 4.1, разрешённые маршруты/параметры, подпуть сервера, пагинация, фильтрация, справочник статусов и отказ в доступе к нему, исключение ключей и содержимого задач из DTO/хранилища/журнала. Выполнены сборка без диагностики TypeScript и полный набор из 29 успешных тестов; после уточнения тестовых ответов повторно прошли обе целевые проверки. Независимое статическое ревью не выявило существенных замечаний. Рабочая логика плагина в этой проверке не менялась: подтверждённых несовместимостей с 4.1 не найдено. ## Ограничения

- Новые версии DSH не заявлены совместимыми: manifest фиксирует проверенный целевой SDK.
- Поиск/сложные фильтры могут требовать загрузки метаданных нескольких страниц на Host. Предел — 10 000 задач с явной индикацией неполноты.
- Запуск сессии может принять промпт, но дальнейшее выполнение агента зависит от модели, учётных данных и разрешений DSH.
- Runtime-журнал фильтрует нативные записи по Redmine. Ошибки загрузки, препятствующие активации Bundle, остаются в штатной диагностике DSH.
