# Независимое ревью MVP

Ревью выполняет отдельная роль `reviewer` в read-only режиме; основной агент интегрирует исправления. База сравнения — начальный коммит `master`.

## Первый прогон

Все восемь первоначальных существенных замечаний исправлены и повторно просмотрены ревьюером:

1. Стандартный пользователь Redmine теперь читается из `id/login/firstname/lastname`, а не требует несуществующего `name`.
2. Операция фиксирует адрес и ключ; смена подключения/режима отменяет предыдущее поколение запросов, чтобы старый ключ не отправлялся новому серверу.
3. Host согласован с UI по `*`, конкретным ID статусов и `#ID`. Признаки закрытости сначала разрешаются из справочника; при его недоступности используются серверные открытая/закрытая группы под общим ограничением выборки.
4. Отказ диагностического хранилища не ломает основные операции.
5. Строковые сообщения и безопасные параметры сохраняются; append сериализован, секреты очищаются.
6. Отказы обязательных этапов health check — ошибки; недоступные необязательные справочники — ограничения. Причины сети/TLS и неоднозначность авторизации обозначаются отдельно.
7. Каталоги передаются нативному реестру для канонизации; сравнения через `toLowerCase` удалены.
8. Mock-запуск использует отдельную непротиворечивую тестовую инструкцию и `.invalid` ссылки.

## Дополнительные замечания при интеграции

- Запросы списка сериализованы, чтобы поздний ответ не перезаписывал более свежие фильтры.
- Браузерные ошибки собираются только при подтверждённом происхождении из модуля Redmine; React ErrorBoundary принадлежит самому плагину. Посторонние сессии/плагины в журнал не копируются.
- История незавершённых запусков должна предоставлять повтор по сохранённому ID операции после переходов и перезагрузки интерфейса.
- Выбор другой папки native picker должен сбрасывать ранее выбранный workspace, чтобы форма отправляла отображаемый путь.

Финальный read-only проход подтвердил эти исправления и не выявил оставшихся P1/P2 в просмотренном коде. Начальный этап `creating` также сохраняется в истории задачи до вызова DSH, чтобы незавершённый запуск был доступен для повтора после перезапуска Host.

Дополнительное замечание P3 о mock-категориях исправлено: категория задачи принадлежит её проекту, а варианты категорий ограничиваются выбранными проектами.

Проверка интерфейса пользователем остаётся отдельной. Независимое статическое ревью не подтверждает внешний вид, рабочее поведение клиента DSH или доступность корпоративного API.
